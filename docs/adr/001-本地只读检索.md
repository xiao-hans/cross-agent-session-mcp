# ADR-001：本地只读检索，不部署跨设备同步

状态：用户已确认本地只读方案。

## 背景

需要跨 Hermes、DSH、WorkBuddy GUI、pi、Cursor Agent CLI 与 Codex 检索本机历史，来源的 JSONL、压缩流和 SQLite 不同。会话可能含个人或工作敏感数据，且现有第三方项目的来源覆盖、同步和写入边界各不相同。

## 选项

1. 直接部署同步项目：来源覆盖较广，但会引入上传、同步和本地写入，与当前需求不符。
2. 直接部署现成纯检索 MCP：接口接近，但已核对的候选未覆盖全部所需来源或不匹配本机实际存储。
3. 借鉴已有开源实现，构建本机只读 MCP：需要承担维护和兼容性责任，但可限定数据范围、来源状态和权限。

## 建议决策

选方案 3；只读且仅本地 stdio，不提供同步、持久索引、外发和会话写入。客户端把结果提交模型或写日志的行为属于独立数据出口，不由本机 stdio 自然阻止。项目范围必须显式授权；一个授权范围可以包含多个项目，默认拒绝无范围查询。

## 后果

需要逐源维护格式、处理缺失或损坏、审查上游许可；活动 SQLite 和 DSH 多帧读取存在兼容性风险。本次仅做轻量测试，以代码审查为主，未经实际验证的来源和安全主张不应视为已验收。连接 Hermes、修改配置、启动长期服务均须另行确认。
