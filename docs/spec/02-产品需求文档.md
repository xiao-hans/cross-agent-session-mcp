# 跨 Agent 会话检索 MCP 产品需求

状态：需求范围已由用户确认。项目目录：`D:/.hermes/workspace/cross-agent-session-mcp`。

## 目标

在本机按日期、项目、Agent 和关键词检索已有会话，返回带可追溯来源的证据，减少跨工具工作回顾、教学交接和项目追踪时的漏源。会话记录只证明记载了什么，不自动证明项目产出或用户已掌握。

## 首版范围

### 必须

- 覆盖 Hermes、DSH、WorkBuddy、pi、Cursor Agent CLI、Codex 六类来源；具体支持以读取实现及后续验证结果为准。
- 允许按来源、时间范围、项目和关键词组合查询；每条结果给出来源、实际执行者、会话标识、消息时间（无时间则标未知）、可定位原文的位置和有限上下文片段。
- 明确返回每类来源的检查状态：已检查有结果、已检查无结果、未启用、不可读取或不支持；部分失败不得伪装成完整覆盖。
- 本机只读；不改原会话，不自动上传、同步、外发或修改其他 Agent 数据。使用指定范围的路径，不把工作与个人内容自动合并；不把私有会话正文写入项目、日志或第三方服务。
- 基于 MCP 供调用方使用，并保留可追溯的错误及限制说明。

### 可选

- 支持有限分页及读取指定结果附近的上下文；不允许通过结果定位越出已授权来源。

### 不在首版范围

- 写入或同步会话，自动生成工作总结、认定任务完成，修改 Hermes/DSH 配置和定时任务，提供远程服务，提交或推送代码。
- Qoder、Claude 等其他 Agent 及 WorkBuddy CLI 的完整独立适配；若未覆盖须明确说明，不能从 WorkBuddy GUI 无记录断定 CLI 无活动。
- 持久化索引、全文副本、模型向量化和第三方上传；如确需引入，另提决策。

## 验收准则

- AC-SEARCH-01：针对支持的来源，按用户给定的来源、时间、项目、关键词返回匹配结果及定位信息；不将文件修改时间冒充消息时间。
- AC-SEARCH-02：来源未配置、不可读、格式不支持或未找到时，区分状态并返回；一个来源失败不隐藏其他来源的状态。
- AC-SEARCH-03：DSH 支持实际 `session.v4.jsonl.zstd` 格式所需的完整多帧解压与消息解析；无法解析时明确报告，不伪装成零结果。
- AC-SEARCH-04：Cursor 数据来源为 Agent CLI transcript 而非仅 IDE 存储；WorkBuddy GUI 索引与正文关联；CLI 归因不从 GUI 空结果推断。
- AC-SEARCH-05：查询限定本地授权来源，不提供写、同步、远程传输或执行任意命令的 MCP 接口；输出有界，不泄漏凭据。
- AC-SEARCH-06：可追溯结果由 Agent、会话 ID、时间、项目或工作目录（存在时）、原文位置、角色、文本片段组成，未知字段标明未知。
- AC-SEARCH-07：支持检索中文，时间按记录内时间和明确时区处理；坏行、未知格式、无时间的处理方式可见且不静默丢弃整个来源。
