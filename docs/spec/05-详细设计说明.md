# 跨 Agent 会话检索 MCP 详细设计说明

状态：设计已由用户确认。需求依据：`03-软件需求规格说明.md`；架构依据：`04-概要设计说明.md`。

## DES-API-01：查询合约

通过 MCP stdio 提供以下接口，类型和错误字段为兼容性约定；不得新增写入或远程传输接口：

### `list_sources()`

返回各来源的 `source`、`enabled`、`status`、受限项目配置是否存在，以及可公开的简短 `reason`；不返回会话正文。状态至少区分 `disabled`、`ready`、`unavailable`、`unsupported`。`ready` 仅说明配置和发现条件具备，不表示已成功完整读取。

### `search_sessions(query, sources, start, end, scope, project, limit)`

- `query`：可选文本关键词，支持中文，无需语义模型；省略时必须同时提供有效的 `start` 和 `end`，以支持按日期回顾且避免无界全量扫描。大小写匹配规则保持一致并在工具说明中明确。
- `sources`：可选指定源；不指定仅查询已启用且已授权的源。
- `start` / `end`：可选含时区的 ISO 8601 时间；采用左闭右开。输入不合法、无时区或起止反向直接报参数错误，不猜测。上层如接受日期，应在调用前按明确时区转换。
- `scope`：必须从本地显式配置的授权范围标识中选择；一个范围可包含多个已批准的项目，以支持按日期跨项目回顾。未经配置、未知或空标识时拒绝查询，不接受任意文件路径。范围配置内的路径是两套独立数据：来源级会话存储根（只绑定来源，同一存储可供该范围内多个已批准项目使用）与项目级 cwd 归属根（只绑定项目，仅用于判定记录属于哪个项目）。
- `project`：可选指定范围内某个项目；省略时搜索该授权范围内全部已批准项目，不包括无法确认项目归属的记录。
- `limit`：范围 1–100，默认 20；片段、总结果、每源扫描资源应设上限并报告截断。
- 返回 `results` 与 `coverage`。结果至少有 `source`、`session_id`、`role`、`timestamp`、`project`、`location`、`snippet`；缺失项为 `null` 并在覆盖信息说明。`source` 与实际 `executor` 分离；无法确定执行者时标未知，不以模型名推断。
- 标识形结果字段（`session_id`、`role`、`executor`）除长度/空白判外还须过**闭合形态门**（审查后补充口径，2026-10-29）：只允许固定字符集（ASCII 字母数字与 `-`、`_`、`.`），不含分隔符、空白、盘符，不以 `.` 起头，整体判否不做前缀保留。来源侧把路径写进这些字段时，结果出 `null` 并在覆盖信息记入降级类别，不得把原值当作标识外出。遮蔽后的正文不属该门：遮蔽层只声称常见凭据形态，正文中的路径形态文本由调用方数据策略处理，本合约不声称已消除。`location` 对外只出不透明引用令牌（接线轮确认，2026-10-29）：发布成功前不给出任何定位值；发布后替换为服务端进程内引用账本发放的 `ctxref:<random>`，不外发 `jsonl:<label>#L<n>` 这类可推导坐标。
- `location` 在适配器内部应能定位至已批准的来源文件/消息，如数据库 session/message ID 或 JSONL 文件/行号；压缩流的行号是解压后事件序号，不伪装成压缩文件的字节偏移。这类坐标只供服务端内部绑定与核对，对客户端的呈现形态统一为引用令牌。
- `coverage` 每源包含 `status`、`matched_count`、`partial`、`skipped_count`、`reason`，并包含 `coverage_scope` 声明本条结论的层级（审查后补充口径，2026-10-29）。状态区分 `searched`、`disabled`、`unavailable`、`unsupported`、`error`；只有完整扫描可称“无匹配”，且该“完整”只对本条 `coverage_scope` 声明的层级成立：单文件协调器给出的是文件级证据，不得被读成整个来源已扫完。任何坏行、未知格式、无时间/无项目无法过滤、解压错误、受限中止或结果截断，均不得把受影响来源表示为完整无匹配。
- 计数分层（审查后补充口径，2026-10-29）：过滤层计数（`records_scanned`/`skipped_count`/`scan_chars`）只回答过滤层判了多少；已读到哪一层由读取/解析/暂存侧快照与 `stage_reached`、`records_withheld` 回答。门禁失败时过滤层计数为零**不等于**“文件未被读取或解析”，两种语义不得混称。`matched_count` 是诊断量，不等于已发布：发布失败时它可非零而 `returned_count`、`results` 必须为零（整批拒绝，不发布前缀）。

### `read_session_context(source, session_id, location, scope, project, before, after)`

以已授权项目及来源中的受控定位信息读取有限上下文。上限由实现固定且文档化；校验位置属于指定来源、会话和项目，路径不能由客户端任意指定。定位信息只给存储对象，因此打开前走存储授权；项目归属另走一次归属核对，两项均通过才读取。找不到、权限不符、格式不可读时返回明确错误，不退化到全盘读取。

定位信息的实现形态（接线轮确认，2026-10-29）：

- `location` 入参是不透明随机引用令牌 `ctxref:<random>`，由检索发布完成后在服务端进程内引用账本（`references.ReferenceLedger`）发放；令牌不编码行号、流标识、路径、版本或任何可拼接字段，客户端无法猜测或伪造可解析形态。
- 账本只存元数据，永不存正文。绑定项：服务密钥（长度前缀哈希的 `scope`+`source`+存储路径+`session_id`）、项目、会话、内部行号/序号/流标识、同趟读取得到的文件版本（句柄卷号+文件标识+已读字节数+单次遍历 SHA-256）、过期时刻。容量硬顶 4096 条活跃条目，有效期 900 秒，满额逐出最旧；卷号、文件标识与摘要只内部保存，不跨越任何协议边界。
- 客户端不能提供行号、版本或尺寸来降级校验：所有绑定与版本核对在服务端完成。校验顺序：令牌可解析且未过期（缺失/过期/逐出同报 `ref_expired`）→服务绑定一致→`scope`/`source`/会话/项目声明与绑定逐项一致（任一不符报 `binding_mismatch`）→重读走同一条授权链，本次同趟版本与账本版本全量相等（同大小改写被摘要识破，报 `file_replaced`）→锚点消息在新候选集按内部坐标仍可定位。任一环节失败均零正文返回。
- `before`/`after` 为整数 0..10（含），越界或非整数在打开任何文件前拒绝；命中窗口总条数硬顶 21。窗口行同样走遮蔽与片段硬顶；发布成功后为窗口内每条记录重新发放新令牌（旧令牌不因此延长寿命），对外位置字段同样是 `ctxref:<random>`。窗口行按记录在行流中的顺序交出，对外行不包含行号、匹配序号或相对锚点距离（审查后收敛口径，2026-10-29）：相邻关系由行序与每条自己的新令牌表达，坐标只在服务端账本内存在。
- 邻位身份口径（审查后补充，2026-10-29）：邻记录不因「靠近锚点」而自动属于本会话。窗口内任一条记录取不出可比会话标识、或取出的标识与断言标识不同，均为相邻关系不可证：零片段拒绍（`window_identity_conflict`），不交出无法归属的正文，也不给它发新令牌。
- 版本取证约束：禁止授权前按路径 stat、禁止读取后按路径再 stat 冒充句柄取证；版本全部来自同一条已授权句柄的同趟读取（身份探针 + `_read_chunk` 增量摘要），部分读取的摘要标记 `complete=False`，不得入账。

### 会话结果发布边界

授权判定拆为两次独立核对：**存储授权**只回答“这个会话对象在当前范围的哪个来源下可读”，结论不携带项目归属；**归属核对**只回答“记录声称的 cwd 属于哪个已批准项目”，结论不携带任何读能力：批准一个项目的归属根只用于判定归属，项目目录树本身仍不可读，正文只能来自已批准的存储根。共享存储可供同一范围内多个已批准项目使用；一项核对通过不得当作另一项也已通过。一条会话发布前需两项均通过，再叠加整流身份核对与脱敏；任一项不成立（包括归属歧义、不命中或无法确认）即丢弃并标记不完整。**但两项通过仍不等于完整授权**：归属核对只证明“这个路径字面与真实位置落在某已批准项目的归属根内”，即一次路径到项目的映射，不证明这条记录确实来自那个项目。记录与项目的实际绑定必须来自来源自身可信格式内的字段（会话库/事件流里的 session、项目、cwd 等标识）、会话身份核对与整流一致性（同一条记录内的定位、会话身份、归属字段互相不矛盾）；只靠“cwd 可以映射”加“存储对象可读”不得宣称完成了来源绑定授权。

归属核对应用 `project` 过滤前，先在**整个范围**内收集候选（字面与真实两套形态）：共享存储下多项目嵌套时，调用方显式指定的 `project` 不能掩盖多项目冲突，归属不唯一即拒绝。

2026-10-28 经用户确认：按行流式读取单个会话时，只在内存中暂存有数量和体积上限的候选结果，不提前向 MCP 客户端输出正文。该会话完整读取后，须核对会话身份、项目归属与本地配置授权，再发布通过过滤和脱敏的结果。身份或项目冲突、归属或授权无法确认时丢弃该会话候选并标记不完整；流被提前中断或候选缓冲触限导致无法完成会话核对时，同样丢弃并标记不完整。候选正文不写入日志、持久索引或临时文件；逐会话处理，避免累积无界内存。来源内元数据可作为归属证据，但不能替代策略层的授权判断。

2026-10-29 经用户确认的同一口径补充：输出侧预算（片段条数、总字符）触限也属于“丢弃并标记不完整”，不是部分发布；失败时必须仍报准确的首拒类别（遮蔽拒、条数触限、总字符触限、接线不等…）与分层计数，以便调用方区分“本应发布但被预算拦下”与“没找到任何东西”。本协调器与外层一律不提供前缀发布选项。

## DES-DATA-01：标准记录与时间

适配器内部标准记录包含 `source`、`session_id`、`executor?`、`role?`、`timestamp?`、`project?`、`location`、`text` 和解析质量标记。消息时间以源内实际值为准，正确处理秒、毫秒、带时区 ISO；未知/无时区不能拿文件 mtime 代替。结果输出统一为带时区的 ISO 8601；缺失时间在时间过滤下不得当成确定命中，并计入不完整覆盖。

## DES-ADAPTER-01：来源契约

每个适配器接收经过策略验证的来源配置与项目范围，逐条产出标准记录和可追踪位置；记录解析、扫描上限、错误和不完整状态都须上报。禁止将原始消息体、密钥、令牌写日志或缓存。解析错误仅输出经过脱敏的原因。

- Hermes：以 SQLite 只读方式按 session/message 读取，先通过表结构检查确认可用字段；profile 路径通过配置显式指定；状态码按既有 `sources/hermes.py` 口径钉死（2026-11-03 按 Cursor 复审 P3 消歧，不再并列两个状态）：**库被写锁占用** → 固定码 `locked`（`HermesAccessCode.BUSY`，有界等待 `busy_timeout_ms` 后放弃），聚合侧记该库 `incomplete` + reason；**存储不存在或无法按只读 URI 打开** → `unavailable`（`HermesAccessCode.UNAVAILABLE`）；**未知 schema/损坏/快照建立不了** → `unsupported`/`snapshot_unavailable` 一类的来源级 `source_unavailable`。`error` 不用于锁，只用于"存储存在但无法解码"（DSH 解码运行时缺失）这类适配器自身无法完成读取的情形。三态（`unavailable`/`unsupported`/`locked`）不得合并，也不得报成 `ready` 或"完整无匹配"。
- DSH：按实际版本化事件流解析，多帧完整解压后流式处理 JSONL；Python 3.14 `ZstdDecompressor` 单次到帧结束不是整个文件结束，应正确处理后续帧和数据错误。
- WorkBuddy GUI：按只读 sessions 的 `id`、`cwd` 关联 JSONL；支持平铺和嵌套的消息结构，过滤工具调用、系统注入及后台通知，缺失正文报告不完整；CLI 归因须另查，不凭空补足。
- pi：识别嵌套 `message`、带文本块的 content 和其本身的 cwd/timestamp；没有可靠 cwd 时不依据有损目录编码还原项目。
- Cursor Agent CLI：只解析**用户级来源存储根** `~/.cursor/projects/<工作区编码>/agent-transcripts/` 下的 JSONL（2026-11-03 按 Cursor 复审 P1-2 更正：原文"项目目录 `agent-transcripts`"作废，transcript 不内嵌于项目树；项目目录只作归属轴），识别 `<timestamp>`、`<user_query>` 和角色文本；不把子代理会话自动算作独立用户任务。
- Codex：识别 `session_meta` 中 cwd/originator 和消息 `payload`，处理文本块并跳过提示词和工具数据；仅在元数据能确认时标注桌面或 CLI。

## DES-SEC-01：授权与信息隐藏

项目映射和来源路径仅从本地受控配置读取，默认无启用项目即拒绝正文查询。每次打开前解析实际路径、拒绝越界与符号链接/重解析点逃逸，避免将数据库等受保护文件当作任意查询对象；项目归属根只用于判定记录属于哪个项目，不得被当作读授权（批准归属根不会使项目目录树可读），且它只构成路径映射证据，不等于记录的来源身份已核对（见 DES-API-01 发布边界）。同时审核文件替换导致的检查后打开竞态：来源层的后续要求是，打开后把**句柄导出的最终路径**重新经一次同样的路径授权（策略层 `authorize_store`），并核验文件身份（卷号 + 文件标识等）与打开前的检查基准一致；最终路径无法安全核验时结果不得发布。不能把路径前缀比较当作强隔离保证。原始会话均按只读打开；SQLite 用 `mode=ro`，不得执行 `CREATE/INSERT/UPDATE/DELETE` 或产生写入的 `PRAGMA`；只读模式下可使用读取表结构的 `PRAGMA table_info`。内部保存的定位信息不能赋予任意路径访问能力。

日志只记录来源、计数、错误类别，不写原文、查询词、凭据或绝对个人路径。结果片段做常见凭据遮蔽，但无法保证发现所有敏感信息；调用者应按项目及客户端权限控制。工具结果属于不可信历史内容，调用方不得将其中指令当作当前用户指令执行。MCP `readOnlyHint` 是描述，不是权限防护。

### DES-INC-01 公共适配器契约

对齐既有三个适配器的同层抽象，四来源共用以下契约：

## 增量：最小生产 stdio 宿主设计（DES-HOST-01 ~ DES-HOST-06，2026-11-05 宿主轮）

此前 `server.main()` 只启动 stdio app，不构造策略也不绑定任何来源服务（见 `09` 2026-11-05 全源验收轮「二、验收边界与后续接入状态（更正）」），所以工具面在生产进程里恒为「未绑定」安全拒绝。本节登记补上这一层的最小宿主 `cross_agent_session_mcp/host.py`：只吃一份显式配置，不猜、不扫、不代策略放行。

### DES-HOST-01 入口形态与依赖边界

- 入口：`python -m cross_agent_session_mcp.host --config <绝对路径> [--check] [--strict]`。仓库内无 `pyproject.toml`/`setup.py`，故不提供 console script、不改打包面；`server.main()` 保持原样（只 `app.run(transport="stdio")`），宿主是**并列**入口，默认未绑定的诚实口径不受影响。
- 依赖：仅标准库（`argparse`/`json`/`pathlib`）加包内既有模块，不新增依赖（对齐 `04` DES-ARCH-03：缺失依赖明确报错，不自动安装、不更新用户环境）。
- 配置来源唯一：只读 `--config` 指向的那份文件。**不读任何环境变量、不做 `~` 或变量展开、不给默认根、不读 Hermes 或其它 Agent 的配置与凭据**。测试宿主 `tests/_bound_stdio_host.py` 的 `CROSS_AGENT_TEST_*` 环境变量入口只属测试面（其文件头已声明「这不是生产入口」），与生产宿主不共享代码路径。
- 配置路径自身过与策略层同一形状门 `policy.is_safe_literal_path`：相对路径会让进程 cwd 参与决定「读哪一份授权」，同一串在不同 cwd 下指向两份授权，因此直接拒（`config_path_unsafe`）。
- 传输只有 stdio：不监听端口、不接受客户端传路径；三个只读工具的入参面没有任何路径位（`05` DES-API-01 不变）。

### DES-HOST-02 配置形状（`schema_version = 1`）

```
{
  "schema_version": 1,
  "scope": "已批准范围标识",
  "projects": [{"name": "项目名", "cwd_roots": ["绝对根" | {"path": "绝对根", "allow_links": false}]}],
  "sources": {
    "pi": {"enabled": true, "mode": "explicit|discover", "store_roots": [...],
           "files": [{"path": "...", "session_id": "..."}], "context_index": 0},
    "hermes": {"store_roots": [...], "stores": [{"path": "state.db", "session_id": "..."}]},
    "cursor_agent_cli": {"store_roots": [...], "mode": "discover", "attribution_project": "项目名"},
    "dsh": {"store_roots": [...], "mode": "discover", "decoder_python": "3.14 解释器绝对路径"}
  }
}
```

- **未知键即拒**（`unknown_key:` + 键名）：配置与实现不同版时宁可拒启动，也不忽略一个可能被误写的授权项；版本不合一律拒（`unsupported_schema_version`）。
- `projects` 与 `sources` 均为必填非空：已批准项目为空＝没有任何可发布正文的范围，等价于 `05` DES-SEC-01 的「默认无启用项目即拒绝正文查询」。
- **逐源显式存储根**：`sources.<id>.store_roots` 缺省即该行报 `unavailable`/`no_store_roots`，绝不退化成「先扫一遍看看」；根数上限沿用 `MAX_DISCOVERY_ROOTS`（16）。读取轴（`store_roots` → `StoreRootGrant`）与归属轴（`projects.cwd_roots` → `CwdRootGrant`）保持两轴独立，批准其一不蕴含另一。
- 两种绑定模式：`explicit` 逐条列举 `files`/`stores`；`discover` 只交给**该来源已有的发现层**（pi / cursor_agent_cli / dsh）。无发现层的来源（hermes、workbuddy、codex）配 `discover` 直接报 `unavailable`/`discovery_not_supported`，不给「先扫库文件」的兼容处理。
- 形状门只产出固定原因码与配置键位点（如 `sources.pi.files[0].session_id`），**原因对象里绝不含文件路径值**。

### DES-HOST-03 绑定流程（fail-closed）

1. `build_policy(config)` → 单 `ScopeGrant` 的 `SessionPolicy`（构造只做形状自检，不触文件系统；扩展来源 `claude_code_cli` 一律不进授权面，不给读轴）。策略建不起来时报告只留一行 `error`，不逐族试绑。
2. `server.reset_bound_services()` 清场：不留上一轮的半对绑定，也不沿用旧引用账本。
3. 全族共用**一个** `ReferenceLedger()`：与 `server._validate_pairing` 的「同账本」硬要求一致，跨族令牌仍由 `service_binding_key` 判族，不会串族发布。
4. 按固定顺序逐族绑定（hermes → dsh → workbuddy → pi → cursor_agent_cli → codex），单族失败只影响该族，与 `list_sources` 的逐源口径一致。
5. 绑定集合**只交付逐条 `authorize_store(..., kind=FILE)` 通过的条目**：被拒（越界/链接/不存在/形态不合）的条目不进集合，只计入 `bindings_denied`；空集合不绑定，报 `unavailable`/`no_bound_files`|`no_bound_stores`。越上限是 `error`/`too_many_bindings:<limit>`，不做静默截断。
6. 发现层的五态不合并：`available`/`disabled`/`unavailable`/`no_candidates_on_facet`/`unsupported` 逐根留在 `discovery_status` 里；「读不下去」绝不表述为「没有会话」，候选相对路径只回填到**已批准的根**上。
7. 绑定门的 `TypeError`/`ValueError` 属宿主配置错误：只记异常类名，不外抛原始消息（消息可能含路径值）。

### DES-HOST-04 各族接线口径与能力边界

- **pi**：两侧都绑整个有界集合（`PiMultiFileSearchService` + `PiMultiFileContextService`），上下文由集合内索引路由；`coverage_incomplete` 直接取自发现结论的 `complete`。
- **行族（codex / cursor_agent_cli / dsh）**：检索轴覆盖整个集合，但 `server._line_context_slots` 每来源只有一个槽位 ⇒ 宿主按 `context_index`（默认 0）用 `search.context_service(index)` 派生**单文件**上下文服务并绑定。这是最小宿主的既定边界：非指定文件的 ctxref 走既有 `binding_mismatch` 口径（服务层既有语义，不是宿主新造的拒绝理由）。宿主不自定路由，只把配置里的索引交给既有工厂。
- **hermes / workbuddy**：只能显式列举 `stores`（`<库路径> + <断言会话标识>`，上限 `MAX_STORES_PER_QUERY`=16）。`HermesStoreRef.session_id`/`WorkBuddyStoreRef.session_id` 是**断言**而非猜测：服务层逐条核对记录身份，漂移即整库降级。WorkBuddy 行为带 `body_publication="source_layer_decides"`——宿主不宣称正文可读（正文布局未逐字核实）。
- **dsh**：`decoder_python` 只在 `bind_dsh_search_service(...)` 传一次；上下文侧**不**再传 `search_service=`/`decoder_python=`，以免用未钉住运行时的原对象覆盖已钉住规格槽（P1-2 的钉住语义）。宿主报告的 dsh 行状态取自 `server._dsh_runtime.usable`，与服务层同源：解码运行时不可用即 `error`/`decoder_runtime_unusable`，`list_sources` 同行也报 `error`，**绝不报 ready**。
- **claude_code_cli**：扩展来源且默认未启用，宿主一律不绑（行 `disabled`/`extension_source_not_enabled`），避免出现「检索有结果但读不到上下文」的半截能力。

### DES-HOST-05 宿主报告与输出面

`bind(config)` 返回 `{scope, projects_authorized, status(ready|unavailable|error), sources:[行]}`；行只含 `source`/`status`/`reason` 与计数（`files_bound`/`stores_bound`/`bindings_denied`/`context_bound`/`context_index`/`discovery_status`/`coverage_incomplete`/`body_publication`），**不含任何路径或会话标识值**。

- 默认模式：人读报告逐族一行走 **stderr**（stdout 留给 stdio 协议通道），随后 `server.app.run(transport="stdio")`。
- `--check`：JSON 报告走 stdout，不启动服务；`status` 为 `error` 时退出码 2。
- `--strict`：任一已启用来源绑定失败（行 `error`）即退出 2，不拉起服务；非 strict 下该族留 `error` 行、其余族继续可用。
- 退出码：配置形状不合 → 2（「配置非法：<位置> → <原因码>」）；配置不可读 → 2（固定「config_unreadable」，**不回显路径**，路径本身含用户目录信息）；策略建不起来 → 2 且不启动服务；其余 0。
- 未绑定任何来源时报告显式提示「本进程未绑定任何来源：`search_sessions` 与 `read_session_context` 一律安全拒绝」，与 `05` DES-API-01 的拒绝语义一致。

### DES-HOST-06 与正文发布边界的衔接

宿主不新增任何发布路径，也不代替策略放行：正文能否发布仍由既有管线在**逐条**层面决定——`session_pipeline` 在解析正文前用可信项目元数据（如行来源的 `trusted_header_cwd`）做 `authorize_attribution`，核对不过的记录逐条丢弃，结果只表现为 `partial`/`complete=false` 与零该条结果。宿主侧的可证事实只有两条：读取轴（存储根）与归属轴（项目根）都只来自本份显式配置；绑定集合里不存在未经 `authorize_store` 通过的位置。范围或绑定拿不到时一律报 `disabled`/`unavailable`，不猜、不静默扫描（`05` DES-SEC-01、`04` DES-ARCH-05 同一取向）。

**状态**：本节所述宿主已落盘并通过静态检查（`compileall`/逐模块导入）；**本轮按调度约束未实跑任何测试**，运行时闭环与 Hermes 侧部署仍未验收（见 `09` 宿主轮、`10` 同日刷新）。
