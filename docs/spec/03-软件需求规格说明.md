# 跨 Agent 会话检索 MCP 软件需求规格

状态：需求与设计范围已由用户确认。需求来源：`02-产品需求文档.md`。

## 功能需求

- SRS-SEARCH-01（对应 AC-SEARCH-01、AC-SEARCH-06；Must）：提供搜索能力，接收关键词、来源集合、时间范围、项目过滤和结果限制，返回会话级或消息级命中、角色、来源、会话标识、时间、项目、位置和片段；缺失元数据显式标未知。
- SRS-SEARCH-02（对应 AC-SEARCH-02；Must）：返回逐来源状态及错误摘要，区分未启用、不支持、不可读取、已读取无匹配和有匹配；部分结果标识不完整及截断情况。
- SRS-SEARCH-03（对应 AC-SEARCH-03；Must）：识别 DSH 版本化压缩 JSONL，处理完整多帧流，按事件提取消息和时间；依赖缺失或格式无法解析时返回明确状态。
- SRS-SEARCH-04（对应 AC-SEARCH-04；Must）：读取 Cursor Agent CLI transcript；读取 WorkBuddy GUI 数据库与对应正文；不得用 GUI 空结果判定 WorkBuddy CLI 无活动。CLI 取证不在首版独立适配范围。
- SRS-SEARCH-05（对应 AC-SEARCH-01、AC-SEARCH-07；Must）：使用消息内时间戳和明确时区解释时间范围，支持中文关键词；无时间和无项目的记录不能凭文件时间或目录名猜测，无法准确过滤时报告不完整。
- SRS-SEARCH-06（对应 AC-SEARCH-01、AC-SEARCH-06；Should）：支持对已授权来源中的指定会话读取有限上下文，并保持原文位置可追溯。
- SRS-SEARCH-12（2026-11-03 补录，2026-11-03 按 Cursor 复审 P2-5 定级修订，Claude Code CLI；**Should**）：读取 Claude Code CLI 会话存储 `~/.claude/projects/<工作区编码目录>/<session-id>.jsonl`，逐行解析 stream-json，从行内提取 `type`（映射角色）、`message`（正文）、`timestamp`（时间）与 `cwd`（项目归属证据），支持时间范围与关键词检索；不认识形态的行与缺失元数据按 SRS-SEARCH-01、SRS-SEARCH-05、SRS-SEARCH-09 的既有口径处理（显式计数或报告不完整，不猜、不静默）。本来源为**扩展来源**：来源 ID 定为 `claude_code_cli`（小写下划线形态，与 `cursor_agent_cli` 同规则），不在 `server.REQUIRED_SOURCES` 六类清单（`hermes`、`dsh`、`workbuddy`、`pi`、`cursor_agent_cli`、`codex`）内，默认 `disabled`、由策略配置启用。定级理由：首版对外口径（AC 与验收清单）不因它改变，且它不在 `REQUIRED_SOURCES` 的必测面内，故记 `Should` 而非 `Must`——旧文同句标 `Must` 又写"默认 `disabled`、首版口径不变"，二者互斥，已作废。参数门侧的口径（见 `05` DES-INC-01 server 接线条与 `09` DES-CL-20261103-03）：`server.py` 对不在 `REQUIRED_SOURCES` 的 `sources` 值现报 `_ERR_SOURCES_UNKNOWN` 拒绝，扩展来源启用前须把 `claude_code_cli` 加入可接受值集合（同集合仍由策略配置的启用状态把关，未启用时点名只报 `disabled`/`unavailable`，绝不打开磁盘）。（适配器尚未编码实现，见 `09-工程实施记录.md` 与 `06-测试计划与测试用例.md` 规划用例大纲。）

## 安全和运行需求

- SRS-SEARCH-07（对应 AC-SEARCH-05；Must）：仅提供只读工具；路径限定在显式启用的本地来源范围，禁止目录穿越、链接越界、任意文件读取及命令执行。SQLite 打开方式与关联文件处理不得修改原数据库；不得以 readOnlyHint 代替底层约束。
- SRS-SEARCH-08（对应 AC-SEARCH-05；Must）：不主动网络传输会话内容、不建立持久全文副本或索引、不把会话正文或凭据写日志；结果数量与片段长度有上限，敏感字段处理策略在设计中明确。
- SRS-SEARCH-09（对应 AC-SEARCH-02、AC-SEARCH-07；Must）：逐行或流式处理大文件；损坏行、未知事件、受锁数据库、解压失败须显式计数或报告，不将部分扫描冒充完整扫描。
- SRS-SEARCH-10（对应 AC-SEARCH-05、AC-SEARCH-06；Must）：工作和个人数据以项目/来源明确隔离，不默认跨范围汇总；默认来源及授权策略在设计阶段确定。
- SRS-SEARCH-11（对应 AC-SEARCH-01；Must）：使用本机 MCP 协议接口；MCP 连接、来源适配与查询结果之间职责分离，依赖不要求强制安装新 App。

## 来源约束

- Hermes：当前机器的 `%LOCALAPPDATA%/hermes/state.db`，还应处理活动 profile 与实际数据路径，不能只依赖 `~/.hermes/sessions`。
- DSH：`~/.dsh/sessions/<工作区编码>/<session-id>/session.v4.jsonl.zstd`。
- WorkBuddy：`~/.workbuddy/workbuddy.db` 和工作区会话 JSONL；GUI 与 CLI 活动区分。
- pi：`~/.pi/agent/sessions/` 下的 JSONL；实际环境的路径可配置。
- Cursor Agent CLI：`~/.cursor/projects/<workspace编码>/agent-transcripts/` 下的 JSONL。**存储根与归属根分离（2026-11-03，Cursor 复审 P1-2 裁决）**：Agent CLI 的 transcript 存储根恒在用户级 Cursor 根下，**不随被检索工作区改变**——某工作区是否出现在候选集，由 `~/.cursor/projects/` 下的工作区编码目录派生，编码规则由实施首轮实测固定并登记；项目目录内的 `.cursor/` 不是 transcript 来源。读取用户级存储根需要独立的**存储授权根**，与**归属授权根**（会话 `project` 声明的比对基准）互不蕴含：批准归属根不会使项目目录树可读，批准存储根也不改变会话归属判定。只读打开，不读取真实会话正文进入研发/审查上下文（取证面为 schema 级）。本来源属 SRS-SEARCH-04 必含清单。
- Codex：`~/.codex/sessions/YYYY/MM/DD/` 下的 JSONL，归档路径按实际情况提供。
- Claude Code CLI：`~/.claude/projects/<工作区编码目录>/<session-id>.jsonl`，stream-json 逐行；会话标识取目录文件名（UUID 形态），`timestamp` 与 `cwd` 在行内；只读打开，不读取真实会话正文进入研发/审查上下文（取证面为 schema 级，见 `05-详细设计说明.md` DES-INC-05）。属扩展来源，默认 `disabled`，由策略配置启用。
